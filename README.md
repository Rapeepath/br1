# Maew — แค็ตตาล็อกสายพันธุ์แมว

เว็บโบรชัวร์สินค้า (React + Vite + TypeScript) นำเสนอแมว 12 สายพันธุ์ยอดนิยมในไทย ครบทั้งนิสัย การดูแล สุขภาพ
สมาคมที่รับรอง ช่วงราคาในไทย และคู่มือก่อนซื้อ ข้อมูลทั้งหมดมาจากการค้นคว้าแบบ deep research พร้อมแหล่งอ้างอิง

## เริ่มใช้งาน

```bash
npm install
npm run dev        # http://localhost:5173  (หลังร้าน http://localhost:5173/admin)
```

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run dev` | เปิดเซิร์ฟเวอร์พัฒนา |
| `npm run build` | ตรวจ type แล้ว build ไปที่ `dist/` (เปิดจาก static host ใดก็ได้ ใช้ hash routing) |
| `npm run preview` | เสิร์ฟ `dist/` ที่ http://localhost:4173 |
| `npm run data` | สร้าง `src/data/*.json` ใหม่จาก `research_notes/` และดาวน์โหลดภาพ (`-- --force` เพื่อโหลดภาพใหม่ทั้งหมด) |
| `npm test` | unit + component tests (Vitest + Testing Library) |
| `npm run test:e2e` | end-to-end (Playwright ใช้ Chrome ที่ติดตั้งในเครื่อง) — desktop และ mobile, ธีมสว่าง/มืด, สแกน axe, ภาพหน้าจอที่ `e2e/screenshots/` |
| `npm run test:all` | typecheck → unit → build → e2e (ใช้วนทดสอบหลังแก้ทุกครั้ง) |

## หน้าในเว็บ

- **สายพันธุ์** (`/`) — hero, ค้นหา/กรอง (กลุ่ม ขน ขนาด) และเรียงลำดับ ตัวกรองถูกเก็บใน URL ย้อนกลับแล้วไม่หาย
- **รายละเอียดสายพันธุ์** (`/breeds/:id`) — ข้อมูลหลัก + 5 แท็บ: ภาพรวม, บุคลิกและนิสัย, การดูแล, สุขภาพ, ก่อนตัดสินใจ
- **เปรียบเทียบ** (`/compare`) — เทียบได้สูงสุด 3 สายพันธุ์ จำรายการไว้ในเบราว์เซอร์
- **คู่มือก่อนซื้อ** (`/guide`) — เช็กลิสต์ฟาร์ม ตารางวัคซีน ค่าใช้จ่าย กราฟช่วงราคา กฎหมาย และการรับเลี้ยง
- **แหล่งข้อมูล** (`/sources`) — แหล่งอ้างอิงรายสายพันธุ์และเครดิตภาพ

## เว็บไซต์ร้านเต็มรูปแบบ

### ส่วนที่ใช้ร่วมกันทั้งสองเว็บ (เพิ่มเมื่อ 6 พ.ย. 2569)

- **URL ปกติ + SEO:** ใช้ BrowserRouter (ลิงก์เก่าแบบ `#/x` จะเปลี่ยนเป็น `/x` ให้เอง) `npm run build` สร้างหน้า HTML สำเร็จรูปทุกหน้า
  ทั้งภาษาไทยและอังกฤษ (`scripts/prerender.mjs` + `src/entry-server.tsx`) พร้อม title, description, canonical, hreflang,
  Open Graph/Twitter, JSON-LD (Store, Product, BreadcrumbList, FAQPage), `sitemap.xml` และ `robots.txt` (กัน `/admin` และ `/api`)
  ทะเบียนหน้าทั้งหมดอยู่ที่ `src/routes.tsx` และตั้งโดเมนจริงด้วยตัวแปร `SITE_URL`
- **ภาษาอังกฤษ:** ทุกหน้ามีคู่ภาษาอังกฤษใต้ `/en/…` (สลับภาษาได้จาก header) ข้อความหน้าจอใช้ `src/i18n/` และ copy ราย
  หน้า ส่วนข้อมูลสินค้าอยู่ที่ `src/data/en.json` ซึ่ง `npm run data` สร้างจาก `research_notes/<หัวข้อ>/i18n/en/*.json`
- **ข้อมูลสดจากหลังร้าน:** หน้าเว็บดึงราคาและสต็อกจาก `/api/public/catalog` และข้อมูลร้านจาก `/api/public/store`
  (`src/lib/live.ts`) ถ้าเปิดแบบไฟล์ static ที่ไม่มี API จะแสดงข้อมูลจากแค็ตตาล็อกแทน
- **ติดต่อและนัดหมาย:** หน้า `/contact` (ฟอร์มสอบถาม, โทร, LINE, แผนที่, เวลาเปิด), `/booking` (เลือกวันและช่องเวลาจาก
  เวลาเปิดร้าน ดาวน์โหลด .ics ได้), ปุ่ม LINE/โทรลอยบนมือถือ และข้อมูลร้านใน footer ทุกฟอร์มส่งเข้า "ลูกค้าที่สนใจ" ใน `/admin`
- **FAQ และ PDPA:** `/faq` (มี FAQPage JSON-LD) และ `/privacy` (นโยบาย + ฟอร์มขอดู/ลบ/แก้ข้อมูล) ทุกฟอร์มต้องติ๊กยินยอม
  มีช่องกันบอท และจำกัด 20 ครั้งต่อ 10 นาทีต่อ IP (`POS_RATE_LIMIT`) เชื่อ `X-Forwarded-For` เฉพาะเมื่อตั้ง `POS_TRUST_PROXY=1`
  (ใช้เมื่อวางหลัง reverse proxy) ผู้จัดการลบข้อมูลส่วนบุคคลของลูกค้ารายใดก็ได้จากหน้าลูกค้าที่สนใจ
- **แกลเลอรีและรีวิว:** ภาพเพิ่มจาก Wikimedia Commons (`public/images/gallery/`, เครดิตในหน้าแหล่งข้อมูล) วิดีโอเล่นเมื่อกด
  เท่านั้น รีวิวจากผู้ชมเว็บต้องรอผู้จัดการอนุมัติใน `/admin` ก่อนแสดง ไม่มีรีวิวจำลองใดๆ
- **รูปภาพ:** `npm run images` (sharp) สร้าง AVIF/WebP ขนาด 480/960/1600 ที่ `public/images/r/` ให้คอมโพเนนต์ `<Picture>`
  (build เรียกให้อัตโนมัติ)
- **หลังร้านเพิ่ม:** ลูกค้าที่สนใจ (สถานะ ผู้ดูแล บันทึก ลบข้อมูลตาม PDPA), นัดหมาย (ปฏิทินรายสัปดาห์), รีวิว (อนุมัติ/ซ่อน),
  ตั้งค่าอีเมล LINE แผนที่ และเวลาเปิดร้าน ภาพรวมมีตัวเลขลูกค้าจากเว็บ เมนูมีตัวเลขรายการใหม่
- **ทดสอบ:** `e2e/site.spec.ts` (หน้าเดิม), `e2e/site-en.spec.ts` (ภาษาอังกฤษ แกลเลอรี รีวิว), `e2e/site-commerce.spec.ts`
  (หน้าใหม่และฟอร์ม), `e2e/admin.spec.ts` ถ้าจะรันสองชุดพร้อมกันให้ใช้ `PW_PORT` และ `PW_DIST` แยกพอร์ตและโฟลเดอร์ build
- **สิ่งที่จำลอง:** ชื่อร้าน ที่อยู่ เบอร์โทร LINE สต็อก การจอง และการชำระเงินเป็นระบบสาธิต (ท้ายเว็บแจ้งไว้) ไม่มีการรับเงินจริง
### เฉพาะ Maew

- `/kittens` และ `/kittens/:id` — ลูกแมวรายตัวจากหลังร้าน (เพศ สี อายุ พ่อแม่พันธุ์ วัคซีน ตรวจสุขภาพ ผลตรวจโรคทางพันธุกรรม
  ไมโครชิป ราคา) ภาพเป็นภาพตัวอย่างของสายพันธุ์และแจ้งไว้ในหน้า
- `/reserve/:id` → `/reservation/:no` — จองพร้อมมัดจำ (2,000 บาท หรือ 10% เมื่อราคาเกิน 40,000) ผ่าน QR พร้อมเพย์จำลอง
  ถือสิทธิ์ 48 ชั่วโมง ที่หน้าร้านกด "เปิดในหน้าขาย" จากหน้าการจองใน `/admin` ระบบจะหักมัดจำให้เอง
- `/care` — การดูแลหลังรับเลี้ยง เงื่อนไขรับประกันสุขภาพ (นโยบายของร้านจำลอง) และการตรวจที่ร้านทำ, `/cost` — คำนวณค่าเลี้ยงดู
  ปีแรก/รายเดือน และผ่อน 0% 3/6/10 เดือน
- หลังร้าน: หน้าลูกแมวและการจอง ลูกแมวนับสต็อกรายตัว (รับเข้าแบบรวมจำนวนไม่ได้) ที่ POS เลือกลูกแมวเป็นตัวๆ
## Deploy บน Vercel

Import repo นี้ใน Vercel ได้เลย ไม่ต้องตั้งค่าเพิ่ม เพราะ `vercel.json` สั่ง build ด้วย `npm run build:vercel`
(`npm run build` แล้วตามด้วย `scripts/vercel-output.mjs`) ซึ่งเขียนโฟลเดอร์ `.vercel/output` ตาม Build Output API
หน้าเว็บที่ build แล้วขึ้น CDN ส่วน `/api/*` รวมถึงหน้าที่ CDN ไม่มีไฟล์ เช่นหน้า 404 จะวิ่งไป function ตัวเดียว
คือ `server/vercel.ts` ซึ่งเรียก API ชุดเดียวกับ `npm run server`

- **ฐานข้อมูล:** ใน Vercel ไปที่ Storage → Create Database → **Upstash for Redis** แล้วเชื่อมกับโปรเจกต์นี้
  (ระบบจะใส่ `KV_REST_API_URL` และ `KV_REST_API_TOKEN` ให้เอง) จากนั้น Redeploy หนึ่งครั้ง
  ฐานข้อมูลทั้งก้อนเก็บไว้ที่ key `<ชื่อ package>:db` จึงใช้ Redis ก้อนเดียวร่วมกันทั้งสองเว็บได้
  ถ้าไม่เชื่อม Redis หลังร้านก็ยังเปิดได้ แต่แต่ละ instance จะเก็บข้อมูลไว้ใน `/tmp` ของตัวเอง
  ข้อมูลจะหายเมื่อ instance ปิด (หลังไม่มีคนใช้ไปสักพัก) และอาจถูกให้ล็อกอินใหม่
- **ตัวแปรอื่น:** `SITE_URL` = โดเมนจริง สำหรับ canonical และ sitemap (ตั้งใน Settings → Environment Variables)
- **ภูมิภาค:** ตั้ง Settings → Functions → Function Region เป็น Singapore (`sin1`) และสร้าง Redis ที่สิงคโปร์
  เพื่อให้ผู้ใช้ในไทยได้ response เร็ว
- ทดสอบในเครื่อง: `npm run build:vercel` แล้วดูผลใน `.vercel/output/` (โฟลเดอร์นี้อยู่ใน .gitignore)

## โครงสร้าง

```
research_notes/<หัวข้อ>/        บันทึกการค้นคว้า (.md) + data/*.json ที่เว็บใช้
reports/                        รายงานสรุปการค้นคว้า
scripts/build-data.mjs          รวมข้อมูล + ตรวจ schema + โหลดภาพจาก Wikimedia Commons
src/data/                       ข้อมูลที่ generate แล้ว (breeds.json, market.json)
src/lib/                        types, ตัวกรอง/เรียง, formatter, state เปรียบเทียบ, ธีม
src/components/  src/pages/     UI (CSS แยกตามคอมโพเนนต์ ใช้ design tokens ใน src/styles/tokens.css)
e2e/                            Playwright tests
.claude/skills/                 skill ที่ติดตั้งสำหรับงานนี้ (frontend-design, webapp-testing)
```

## แนวทางการออกแบบ (ธีมพาสเทลเป็นมิตร)

- ธีมสว่างเป็นค่าเริ่มต้นเสมอ ไม่ตามโหมดมืดของระบบ (สลับเป็นธีม "กลางคืน" โทนม่วงเข้มได้จากปุ่มบนเฮดเดอร์ และจำค่าไว้)
- โทน pet friendly: พื้นครีม แถบสลับสีแอปริคอต ตัวอักษรสีน้ำตาลโกโก้ (เหมือนขนแมวลายเสือ) สีหลัก **teal** สำหรับปุ่มและลิงก์ สี **ส้มขิง** สำหรับบรรทัดที่สองของหัวเรื่องและมาตรวัด พื้นนุ่มของเมนู/แท็บ/แคปซูลเป็นมินต์ (`--soft`) และสีพาสเทล 6 โทน (พีช มินต์ ฟ้า ลาเวนเดอร์ เนย ชมพู) แต่ละโทนมีสีตัวอักษรคู่ที่อ่านได้ ≥5:1 ใช้ผ่านคลาส `.tone-*` (ลาเวนเดอร์ไม่ใช้เป็นค่าเริ่มต้นแล้ว)
- ตัวอักษร Nunito (ละติน/ตัวเลข ปลายมน) + Mitr (หัวเรื่องไทย) + Noto Sans Thai (เนื้อหา)
- ทุกอย่างโค้งมน: การ์ด 30px ไทล์ 22px ปุ่ม/ชิป/แท็บทรงแคปซูล ปุ่มหลักนูนมีขอบกดลง เงานุ่มอมม่วง + ไฮไลต์แบบดินปั้น
- ใช้พื้นผิวสีเติมแทนเส้นบาง: การ์ดขาวบนแถบพาสเทล ไทล์สี ฟองตัวเลข/ไอคอนกลม ป้ายหัวข้อเป็นแคปซูลพร้อมไอคอนอุ้งเท้า
- รองรับมือถือ, คีย์บอร์ด, screen reader, reduced motion และผ่าน WCAG 2.1 AA ทั้งสองธีม

## ระบบหลังร้านและ POS จำลอง (`/admin`)

ระบบขายหน้าร้านที่ใช้งานได้จริงบนข้อมูลจำลอง: ขายลูกแมว (เกรดเลี้ยง/เกรดประกวดของทั้ง 12 สายพันธุ์) อาหาร อุปกรณ์
และบริการสุขภาพ ตัดสต็อก ออกใบเสร็จ คืนเงิน เปิดปิดกะเงินสด และดูรายงาน ข้อมูลเก็บในเซิร์ฟเวอร์ Node (`server/`)

| วิธีเปิด | ที่อยู่ |
|---|---|
| `npm run dev` | เว็บ http://localhost:5173/ หลังร้าน http://localhost:5173/admin |
| `npm run build && npm run server` | เว็บ http://localhost:3001/ หลังร้าน http://localhost:3001/admin (ไม่ต้องใช้ Vite) |
| `npm run preview` | หลังร้านจาก `dist/` ที่ http://localhost:4173/admin |
| `npm run pos:reset` | ลบข้อมูลเดิมแล้วสร้างข้อมูลจำลอง 60 วันชุดใหม่ที่จบที่วันนี้ (ผู้จัดการกดได้จากหน้าตั้งค่าด้วย) |

รหัสทดลอง: **ผู้จัดการ** ปวีณา ใจดี `1111` · **พนักงาน** ธนกร มีสุข `2222` และศิริพร แสงทอง `3333`
พนักงานคืนเงินหรือปรับสต็อกได้เมื่อผู้จัดการใส่ PIN ให้ แก้ราคา ตั้งค่าร้าน และสร้างข้อมูลใหม่ได้เฉพาะผู้จัดการ

หน้าในระบบหลังร้าน (hash routing เช่น `/admin/#/pos`)

- **ภาพรวม** ยอดขายวันนี้เทียบเมื่อวานช่วงเวลาเดียวกัน กราฟยอดขาย 30 วัน สินค้าขายดี ช่องทางชำระ หมวด สินค้าใกล้หมด บิลล่าสุด กะที่เปิดอยู่
- **ขายหน้าร้าน** ค้นหาและแตะสินค้าเพิ่มลงบิล ปรับจำนวน ส่วนลดรายการ/ท้ายบิล (บาทหรือ %) เลือกหรือเพิ่มลูกค้า
  ราคาและสต็อกคิดที่เซิร์ฟเวอร์ (`/api/quote`) ชำระด้วยเงินสด (ปุ่มจำนวนเงินด่วนและเงินทอน) พร้อมเพย์ (QR จำลอง)
  บัตร (อนุมัติจำลอง) หรือโอน แล้วออกใบเสร็จรับเงิน/ใบกำกับภาษีอย่างย่อที่พิมพ์ได้ (ขนาดกระดาษ 80 มม.)
- **รายการขาย** กรองตามช่วงวัน สถานะ ช่องทาง พนักงาน ค้นหา ดูรายละเอียดบิล พิมพ์ซ้ำ และคืนเงิน
- **สินค้าและสต็อก** ราคา ต้นทุน กำไร สต็อก ยอดขาย รับสินค้าเข้า ตรวจนับ บัตรสต็อกพร้อมยอดคงเหลือ และข้อมูลสายพันธุ์ครบทุกหัวข้อ
- **ลูกค้า** รายชื่อ ยอดซื้อสะสม เพิ่ม/แก้ไข และประวัติการซื้อ
- **กะและเงินสด** เงินที่ควรมีในลิ้นชัก นำเงินเข้า/ออก ปิดกะพร้อมแสดงเงินเกิน/ขาด และประวัติกะ
- **รายงาน** สรุปยอด กำไรขั้นต้น VAT ยอดรายวัน รายชั่วโมง รายสินค้า หมวด ช่องทาง พนักงาน และส่งออกบิลเป็น CSV (เปิดใน Excel ได้)
- **บันทึกกิจกรรม** ทุกการกระทำในระบบ ใคร ทำอะไร เมื่อไร
- **ตั้งค่า** ข้อมูลร้านบนใบเสร็จ อัตรา VAT ตัวอย่างใบเสร็จ พนักงาน และข้อมูลฐานข้อมูล

สิ่งที่จำลอง: ยอดขายย้อนหลัง 60 วัน (สุ่มแบบกำหนดค่า seed จึงได้ชุดเดิมทุกครั้งที่สร้างใหม่) ลูกค้า 32 ราย สต็อก กะเงินสด และการชำระเงิน
ทุกช่องทาง ไม่มีการตัดเงินจริงและใบเสร็จไม่ใช่เอกสารทางภาษีจริง ฐานข้อมูลเป็นไฟล์ JSON ที่ `.pos-data/db.json`
(เปลี่ยนได้ด้วยตัวแปร `POS_DB`) e2e ใช้ไฟล์แยก `.pos-data/e2e.json` ที่สร้างใหม่ทุกครั้ง

```
server/types.ts      รูปแบบข้อมูลที่ใช้ร่วมกันระหว่างเซิร์ฟเวอร์และหน้าหลังร้าน
server/catalog.ts    สินค้า พนักงาน ลูกค้า และพฤติกรรมการขายของร้าน Maew
server/logic.ts      กติกา POS: คิดราคา VAT ตัดสต็อก คืนเงิน กะเงินสด รายงาน (มี unit test ใน logic.test.ts)
server/seed.ts       สร้างข้อมูลย้อนหลัง 60 วันผ่านกติกาเดียวกัน
server/api.ts        REST API (/api/*) และ vite-plugin.ts ที่ต่อ API เข้ากับ npm run dev/preview
src/admin/           หน้าหลังร้าน (React) ใช้ design tokens เดียวกับเว็บ
e2e/admin.spec.ts    ทดสอบทุกหน้า (axe ธีมสว่าง/มืด desktop/mobile) และขั้นตอนขาย คืนเงิน รับของ เพิ่มลูกค้า รายงาน กะ
```
> ข้อมูลเพื่อประกอบการตัดสินใจ ราคาเป็นช่วงโดยประมาณจากตลาดไทย ณ ตุลาคม 2569 เรื่องสุขภาพควรปรึกษาสัตวแพทย์
